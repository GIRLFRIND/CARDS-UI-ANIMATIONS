How the scrolling card animation works

The four story cards share one frame. At the start they are stacked, with a small offset so you can see the cards behind the top one. As you scroll through the tall story section, each card in turn slides up and the next card is revealed.

1. Make a scroll runway

The .stories section is taller than the viewport. That extra height gives the animation time to progress while the card frame remains pinned.

2. Pin one frame and stack the cards

.story-stage uses position: sticky to stay in view. Each .story-card uses position: absolute to occupy the same frame. The cards are layered by z-index; a small vertical offset hints that more cards are underneath.

3. Turn scroll position into animation progress

JavaScript measures how far the page has moved through the story section. It maps that distance to a number from 0 to 3 (the four cards have indexes 0 through 3). The current number identifies which card is being shown.

4. Move cards with a CSS custom property

For cards already passed, JavaScript updates --offset to slide them upward by one frame. Cards still ahead keep their small stacked offset. CSS applies the value with translate3d, so moving a card doesn’t reflow the others.

5. Keep updates smooth and accessible

  • requestAnimationFrame batches scroll updates to the browser’s next paint.
  • The prefers-reduced-motion setting keeps the cards stacked without the scrolling movement.
  • The CSS media query adjusts the frame and spacing for smaller screens.

The core idea, simplified

progress = scrollDistance / scrollableDistance * lastCardIndex
offset = cardIsPassed ? -distancePassed * frameHeight : cardsAhead * stackGap
